# MyList Update Notifier — แผนงาน

สถานะ: **วางแผนเท่านั้น ยังไม่ได้ลงมือ** (2026-11-02)

## เป้าหมาย
เช็คว่าหนัง / ซีรีส์ / อนิเมะ / มังงะ / เกม ใน MyList มีอัปเดตใหม่ไหม แล้วแจ้งเข้า Discord วันละครั้ง

## ข้อสรุปที่ได้
- **ไม่ใช้ Hermes (LLM) ไล่ค้นเว็บ**: แผน ChatGPT ฟรีโควตาไม่พอ ผลมั่วได้ และต้องคอยดูแล
- **ใช้สคริปต์ + API ฟรี + Discord webhook**: ไม่เปลืองโควตา LLM และแทบไม่ต้องดูแล
- ลิสต์ยังสั้น แต่จะยาวขึ้นเรื่อยๆ จึงคุ้มทำแบบสคริปต์
- Hermes ค่อยเพิ่มทีหลัง ถ้าอยากสั่งงานผ่าน Discord ได้ด้วย เช่น "เช็คตอนนี้เลย"

## Flow
```
list.db (NAS) → สคริปต์เช็ค → เทียบกับ state รอบก่อน → มีของใหม่ → Discord webhook
```

## ขั้นตอน

### 0. ของที่ต้องพร้อมก่อน
- [ ] สร้าง Discord webhook: Edit Channel → Integrations → Webhooks → New Webhook → Copy URL
- [ ] สมัคร TMDB API key (ฟรี) ไว้ใช้กับหนังและซีรีส์
- [ ] เก็บ webhook URL และ key ใน `.env` ห้าม commit ลง git

### 1. ดูโครงสร้างข้อมูลใน `list.db` (อ่านอย่างเดียว)
- ที่อยู่: `/volume1/docker/myprivatelist/data/list.db` (ใช้ WAL ดังนั้นห้าม `cp` ไฟล์ `.db` ตัวเดียว)
- ถ้าแอปมี HTTP API ที่พอร์ต `3210` ให้อ่านผ่าน API แทน
- ดูว่ามีหมวดอะไรบ้าง แต่ละเรื่องเก็บชื่อ, URL/ID, สถานะ (กำลังดู/จบแล้ว) ไว้ไหม
- เช็คเฉพาะเรื่องที่ยังติดตามอยู่

### 2. จับคู่แต่ละเรื่องกับแหล่งข้อมูล
| ประเภท | แหล่ง | ดูอะไร |
|---|---|---|
| หนัง/ซีรีส์ | TMDB | ซีซันใหม่, วันออกตอนถัดไป, วันฉาย |
| อนิเมะ | AniList GraphQL (ไม่ต้องใช้ key) | ตอนถัดไป, ประกาศซีซันใหม่ |
| มังงะ | MangaDex | ตอนใหม่ |
| เกม | Steam News API | แพตช์, DLC, ข่าว |

- ครั้งแรกต้องจับคู่ชื่อเรื่องกับ ID เรื่องที่ชื่อกำกวมให้ยืนยันเองครั้งเดียว
- เก็บ ID ที่จับคู่แล้วในไฟล์แยก ไม่แก้ `list.db`

### 3. เก็บ state
- ไฟล์ JSON เล็กๆ บันทึกว่าแต่ละเรื่องเห็นข้อมูลล่าสุดถึงตรงไหนแล้ว
- แต่ละรอบเทียบกับ state แล้วส่งเฉพาะสิ่งที่เปลี่ยน

### 4. ส่ง Discord
- ส่งเป็น embed แยกหมวด (📺 🎬 📖 🎮)
- ไม่มีอะไรใหม่ก็ไม่ต้องส่ง
- ข้อจำกัด: embed หนึ่งยาวได้ประมาณ 4096 ตัวอักษร ข้อความหนึ่งมีได้ 10 embed ส่งได้ประมาณ 30 ข้อความต่อนาทีต่อช่อง

### 5. ตั้งเวลา
- รันบน NAS ที่เปิดตลอดอยู่แล้ว ผ่าน Synology Task Scheduler หรือ cron ใน container
- รันวันละครั้ง

### 6. ทดสอบ
- รันแบบ dry-run ที่แค่ print ผล ยังไม่ส่ง
- ส่งเข้าช่องทดสอบก่อน แล้วค่อยเปลี่ยนเป็นช่องจริง

## ตัวอย่าง webhook
```bash
curl -H "Content-Type: application/json" \
  -d '{"content": "🎬 ทดสอบ MyList notifier"}' \
  "$DISCORD_WEBHOOK_URL"
```

## สิ่งที่ยังต้องตัดสินใจ
- อะไรนับเป็น "อัปเดต": ตอนใหม่ / ประกาศซีซันใหม่ / ตัวอย่างหนัง / แพตช์เกม
- เอามังงะด้วยไหม
- เกมที่ไม่ได้อยู่บน Steam จะข้ามไปก่อน หรือใช้ RSS แทน

## หมายเหตุเรื่อง Hermes
- **ตัวจริงรันบน NAS** (`/volume1/docker/hermes-agent`) ใช้ provider `openai-codex` model `gpt-5.6-terra` และ Discord bot "JARVIS" ใช้งานได้อยู่แล้ว (ดู `docs/hermes-discord.md`)
- ตัวบน Windows (`%LOCALAPPDATA%\hermes`) เป็นอีก install หนึ่ง ไม่ได้รันมาตั้งแต่ 2026-09-08 วันที่ 2026-11-02 ผมเปลี่ยน model ของตัวนี้จาก `gpt-6-astra` เป็น `gpt-5.6-terra` แล้ว
- ทางเลือกเพิ่ม: ไม่สร้าง webhook ก็ได้ ให้สคริปต์ส่งผ่าน Hermes cron หรือ bot JARVIS แทน แต่วิธีนี้จะกินโควตา LLM ทุกครั้งที่ส่ง webhook จึงยังถูกกว่า
